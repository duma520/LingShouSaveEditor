# 第一篇 · 极简版（3 分钟上手）

> 如果你**只想快速改个道具数量**，看完这一篇就够了。

## 1.1 三步搞定

1. **打开**：双击 `LingShouSaveEditor.py`（或打包好的 exe），点工具栏「**打开**」，选中你的存档文件（一般在游戏目录 `SaveData\custom0.es3`）。
2. **改**：表格里双击某道具的「数量」列，输入新数字，回车。
3. **保存**：点工具栏「**保存**」。完事。

## 1.2 五个最常用的按钮

| 按钮 | 干什么 |
|------|--------|
| **打开** | 载入存档文件 |
| **全部改为 9999** | 把所有道具数量一键设成 9999（可勾「跳过铜钱」） |
| **保存** | 写回原文件 |
| **另存为** | 存成一个新文件（推荐先另存，安全） |
| **粘贴** | 不用文件，直接粘贴存档文本内容 |

## 1.3 三个最重要的安全习惯

1. **先备份**：改之前把 `custom0.es3` 复制一份存到别处。
2. **先另存**：第一次改，用「另存为」存成 `custom0_改.es3`，测试没问题再覆盖原文件。
3. **看状态灯**：「打开」左边的小圆点，**绿=已保存、红=有改动没保存**，红的时候别忘了点保存。

## 1.4 记住一句话

> **这个工具只改存档，不改游戏程序。所有修改都能用备份还原。**

# 第三篇 · 完全新手指南（零基础入门）

> 假设你**从没用过任何存档修改器**，连 Python 是什么都不知道。这一篇带你从 0 开始。

## 3.1 这个软件是什么？能干什么？

**一句话**：它是《灵兽江湖》这款游戏的**存档修改器**。

**打个比方**：

> 游戏存档就像一本账本，记录了你游戏里的一切——有多少钱、有什么道具、队友多少级、学了哪些功法。
> 这个修改器就是一支**可以改写账本的笔**，让你不用打几百小时游戏，就能直接改数字。

**它能改什么？（完整列表）**

| 类别 | 能改什么 | 举例 |
|------|---------|------|
| **道具** | 名称、数量 | 把「铜钱」改成 21 亿；补齐所有道具 |
| **主角属性** | 等级、经验、力道/感知/灵气/体魄/经脉/速度、气血、天赋点、已用点 | 等级改成 9999 |
| **队友属性** | 同上（每个队友独立） | 把队友「藏玲珑」等级改成 9999 |
| **武学经验** | 各类武学的经验值 | 一键全 999999 |
| **生活技能** | 各生活技能经验 | 一键全 999999 |
| **六维当前值** | 力道/感知/灵气/体魄/经脉/速度当前值 | 一键全 999 |
| **好感度** | 每个好友的好感度 | 一键全 999 |
| **地图标注点** | 已到过的地点 | 补齐所有跳转点（236 个） |
| **剧情变量** | 善恶值 | 改成 0（中立）或任意值 |
| **商店 NPC** | 卖品、装备、折扣、刷新日 | 五折优惠；上架所有装备 |
| **蛊虫** | 显示名、属性、技能、偏好、培养值 | 力道/灵气/体魄改 9999 |
| **装备** | 等级、耐久、装备技能、词条技能 | 加装备、删装备、改技能等级 |
| **功法** | 内功/武功/绝技/轻功增删 | 一键学全 1045 门 |
| **队伍状态** | 加入队伍 / 改为离队 | 把离队队友拉回队伍 |

**它不能改什么？**

- ❌ 不能改游戏程序本身（那是「作弊器」，本工具只改存档）
- ❌ 不能改游戏内的实时状态（必须先退出游戏再改存档）
- ❌ 不能保证改完游戏不崩（有些数值游戏有校验，改太夸张可能出问题）

## 3.2 安装与运行（三种方式）

### 方式一：用打包好的 exe（最简单，适合普通玩家）

1. 从 GitHub 下载打包好的 `LingShouSaveEditor.exe`（在 `build_output` 目录里）。
2. 双击运行。
3. 完事，不用装任何东西。

### 方式二：用 Python 源码运行（适合想自己改代码的人）

1. 装 Python 3.10（官网 python.org 下载）。
2. 装依赖：打开命令行，输入 `pip install PySide6`。
3. 双击项目根目录的 `1.bat`，或者命令行运行 `python LingShouSaveEditor.py`。

### 方式三：自己打包 exe（适合想分享给别人的人）

1. 装 Python 3.10 和 PySide6。
2. 装 Nuitka：`pip install nuitka`。
3. 双击 `0_nuitka_pyside6_clang_auto.bat`。
4. 打包结果在 `build_output` 目录。

> **注意**：打包脚本只编译 `LingShouSaveEditor.py` 这一个文件，其它 json 数据文件会自动打进 exe 旁边。

## 3.3 第一次使用：完整的「打开→改→保存」流程

### 步骤 1：找到你的存档文件

游戏的存档一般在：

```
<游戏安装目录>\灵兽江湖\灵兽江湖\SaveData\custom0.es3
```

常见的存档文件名：
- `custom0.es3` ~ `custom17.es3`：手动存档
- `quick1.es3` ~ `quick3.es3`：快速存档
- `Auto1.es3` ~ `Auto3.es3`：自动存档
- `note1.es3` ~ `note3.es3`：笔记存档

### 步骤 2：备份！（重要）

把 `custom0.es3` 复制一份，改名为 `custom0.es3.bak`，放到别的地方。

> **为什么要备份？** 万一改坏了，把 `.bak` 改回 `.es3` 覆盖，就恢复原样了。

### 步骤 3：打开存档

1. 运行修改器。
2. 点工具栏「**打开**」。
3. 选中 `custom0.es3`。
4. 等待几秒（大存档要 5~10 秒，窗口不卡，左下角有进度）。

打开后你会看到：

```
┌─────────────────────────────────────────────────┐
│ [●] 打开  打开上次  最近▾ | 重新读取 | 粘贴  保存 …│  ← 工具栏（●是状态灯）
├─────────────────────────────────────────────────┤
│ 道具 | 主角 | 队友·xxx | 队友·yyy | …             │  ← 页签
├─────────────────────────────────────────────────┤
│ 源: C:\...\custom0.es3                          │  ← 源文件路径
│ 搜索: [____________]  [自动匹配▾]                │  ← 搜索框
├─────────────────────────────────────────────────┤
│ #  │ 道具名称          │ 数量                    │  ← 表格
│ 1  │ 铜钱              │ 998720404               │
│ 2  │ 2纯铜矿           │ 9999                    │
│ …  │ …                 │ …                       │
├─────────────────────────────────────────────────┤
│ [全部改为9999] □跳过铜钱 | 全部改为:[9999] [按钮] │  ← 批量工具
│ [＋新增道具] [一键添加全部] [－删除选中]  总数:N │
└─────────────────────────────────────────────────┘
```

### 步骤 4：改点什么

**例 1：把铜钱改成 10 亿**

1. 在搜索框输入 `tq` 或 `tongqian`，表格过滤出「铜钱」。
2. 双击「数量」列的单元格。
3. 输入 `1000000000`，回车。
4. 看到状态灯变**红**（有未保存修改）。

**例 2：一键把所有道具改成 9999**

1. 点「**全部改为 9999**」按钮。
2. 铜钱默认被跳过（因为勾了「跳过铜钱」），要改铜钱就先取消勾选。

**例 3：补齐所有道具**

1. 点「**＋ 新增道具**」。
2. 在左栏分类树勾选「全勾选」。
3. 勾选「仅显示缺少（未在个人背包）」。
4. 点「全选」→ 点「添加所选」。

### 步骤 5：保存

1. **第一次改建议先「另存为」**：点「另存为」，存成 `custom0_new.es3`。
2. 测试游戏能正常读取新存档后，再用「保存」覆盖原文件。
3. 保存成功后，状态灯变**绿**（已保存）。

### 步骤 6：进游戏验证

1. 启动游戏。
2. 载入存档。
3. 看看改动是否生效。

# 第四篇 · 功能详解（按模块逐个讲透）

## 4.1 道具页

### 4.1.1 表格基础操作

**表格三列**：
- `#`：行号（在完整列表里的原序号，搜索过滤后仍显示原号）
- `道具名称`：道具名（双击可改）
- `数量`：道具数量（双击可改，范围 0 ~ 21 亿）

**双击改值**：双击单元格 → 输入新值 → 回车。
- 名称：不能为空、不能含 `{ } " \` 和换行、不能与其它道具重名。
- 数量：0 ~ 2,100,000,000（21 亿）。

**多选**：按住 `Ctrl` 点选多个，或按住 `Shift` 选一段，或鼠标拖动。

**删除**：选中后点「－删除选中」，或直接按 `Delete` 键。

### 4.1.2 搜索过滤

搜索框支持**四种输入**（在「自动匹配」模式下）：

| 输入方式 | 例子 | 匹配 |
|---------|------|------|
| 中文子串 | `铜` | 所有名字含「铜」的 |
| 拼音全拼 | `tongqian` | 铜钱 |
| 拼音首字母 | `tq` | 铜钱、铁锹、糖球… |
| 数字 | `2` | 名字含「2」的 |

**匹配方式**（右上角下拉）：
- **自动匹配**：四种都试（默认）
- **仅中文**：只按中文子串
- **仅拼音/首字母**：只按拼音

**注意事项**：
- 搜索时 `#` 列显示的是**完整列表里的原序号**，不是过滤后的行号。
- 删除选中、双击编辑**只作用于当前显示的行**。
- 点搜索框的 ✕ 或清空文字，恢复全部。

### 4.1.3 表头排序

**点击表头**：
- 第一次点「道具名称」= 按名称**升序**（A→Z）
- 再点一次 = 按名称**降序**（Z→A）
- 换点「数量」= 按数量升序
- 同列再点 = 反向

**右键表头**：弹出菜单，可直接选「名称升序 / 名称降序 / 数量升序 / 数量降序」。

**注意**：排序**直接作用于数据**（不是视觉排序），所以排序后双击编辑、删除仍然对应正确的道具。

### 4.1.4 批量改数量

| 按钮 | 作用 |
|------|------|
| **全部改为 9999** | 所有道具改成当前目标值（按钮文字会跟着目标值变） |
| **跳过「铜钱」** | 勾上后批量改时不动铜钱 |
| **全部改为 [数字框] [按钮]** | 自定义目标值，然后点「全部改为」 |
| **选中改为 [目标值]** | 只改表格里选中的行 |
| **一键 _GetTimeNew→0** | 把所有道具的获取时间戳清零 |

**目标值会被记住**：改了数字框后自动存进 `设置.json`，重开程序仍是这个值。

### 4.1.5 新增道具

点「**＋ 新增道具**」打开一个**双栏对话框**：

**左栏：分类树（可勾选）**

按游戏数据集的路径分级：
```
equip 装备(435)
item 道具(2480)
recipe 配方(644)
bookcontent 书籍(194)
kangfu 武功秘籍(1044)
skillcom 技能合成(155)  ← 这个不在道具页新增里显示
shanhailu 山海录(25)
```

勾选逻辑：
- 勾**大分类**：包含该分类及**全部下级**
- 展开后**反选子分类**：可精确排除（父分类变「半选」）
- **默认不勾选**：勾了才会在右侧显示

**右栏：候选列表**

- 顶部搜索框：中文/拼音/首字母/数字
- 「仅显示缺少（未在个人背包）」：只列你还没有的
- 「全选 / 清空选择」：一键操作
- 底部统计：库总数 / 当前分类 / 已选 / 隐藏黑名单数

**底部**：
- 「数量（本次新增道具统一）」：新道具的初始数量
- 「添加所选」：确认添加

**快捷操作**：
- **双击**某个候选 = 直接添加
- 搜索框里**输入自定义名 + 回车** = 加自定义道具
- 名称含中文弯引号（如 `碎“肉”`）会自动转义成游戏格式

### 4.1.6 一键添加全部道具

点「**一键添加全部道具**」：
- 从 `道具名.json`（4567 个）读取全部道具名
- 剔除已有、装备类（equip）、技能合成类（skillcom）、道具黑名单
- 全部以 9999 数量加入

### 4.1.7 添加装备（EquipHad）

点「**＋ 添加装备…(EquipHad)**」：
- 只显示装备类（equip）
- **同名可多件**：「件数」填 N = 加 N 个同名实例
- 名字前导数字 = 等级（如 `5斩龙剑` 的等级是 5）

**和「新增道具」的区别**：
- 道具 → ItemHad
- 装备 → EquipHad
- 不能混（游戏规定装备不进 ItemHad）

### 4.1.8 一键整理道具名

点「**一键整理道具名**」：
- 把当前表格里的所有道具名，去重后合并进 `道具名.json`
- 用于你手动新增了自定义道具后，同步进库

## 4.2 商店 NPC 页

### 4.2.1 左侧：NPC 列表

- **分类下拉**：按地方/门派过滤（安居城/禾兴城/黑市/门派…）
- **搜索框**：中文/拼音/首字
- **多选**：Ctrl 点选多个，配合批量应用

### 4.2.2 右侧三个标签页

**①「卖品」页**

- 表格显示该 NPC 的 SellItems（卖品名称 + 数量）
- 「＋ 添加卖品…」：从道具名库搜索/多选添加
- 「删除选中卖品」：整件下架
- 「选中改数量」：改成批量目标值

**②「装备」页**

- 表格显示该 NPC 的 SellEquips（装备名称 + 件数）
- 「＋ 添加装备…(SellEquips)」：只显示 equip 类，同名可追加
- 「删除选中装备」：整种下架（同名所有件一起删）
- 「选中改件数」：改成批量目标值（0 = 删除整种）

**③「NPC 参数」页**

- **折扣 Discount**：0~1，1=无折扣，0.5=五折。单店改 + 「默认 0.1」
- **刷新日 RefreshDay**：单店改 + 「默认 1」
- **批量折扣/刷新日**：数字框 + 「应用到选中 NPC」/「应用到全部 NPC」

### 4.2.3 批量目标值（记忆）

顶部的「批量目标（数量/件数）」数字框是**共享**的：
- 卖品「选中改数量」用它
- 装备「选中改件数」用它
- 改动自动记忆到 `设置.json`

## 4.3 蛊虫页

### 4.3.1 蛊虫是什么？

游戏里的宠物/召唤物，存在存档的 `ChongHad` 段。

### 4.3.2 左侧：蛊虫列表

格式：`序号. 显示名 · 数据集名`

### 4.3.3 右侧四个标签页

**①「属性」页**

| 字段 | 说明 | 默认 |
|------|------|------|
| `_CustomName` | 显示名 | 数据集名 |
| `_Love` | 喜爱标记 | false |
| `_Foster` | 培养值 | 0 |
| `_FosterMax` | 培养上限 | 9999 |
| `Power` | 力道 | 9999 |
| `Agility` | 灵气 | 9999 |
| `PhysicalPower` | 体魄 | 9999 |
| `_TotalProperty` | 累计属性 | 改三项后自动写 0 |

> **重要**：改了三项属性（力道/灵气/体魄）后，`_TotalProperty` 会自动写成 0——这是游戏规律，不要手动改它。

**②「技能 _Skill」页**

- 表格形式：状态名 → 数值
- 蛊虫可用状态**只有 5 种**：中毒 / 流血 / 着火 / 点穴 / 冰冻
- 「本只：全部→目标值」：所有状态改成目标值
- 「本只：补齐全部状态(5 种)」：补上缺的 5 种
- 「本只：写入全部技能库」：把 277 条战斗技能全写进去（存档会变大）
- 「＋ 添加状态…」：从技能库挑
- 「－ 删除选中行」

**③「偏好 _Preference」页**

- 状态倍率，1.1 = 110%
- 操作同 _Skill 页

**④「批量（全部蛊虫）」页**

对所有蛊虫一次性操作：
- `_Skill` / `_Preference`：补齐 5 种 / 写入全部技能库 / 清空
- 三项属性：一键设为目标值（默认 9999）
- `_FosterMax`：一键设为目标值（默认 9999）

### 4.3.4 添加蛊虫

点「**＋ 添加蛊虫…**」：
- 分类树：冰系/毒系/穴系/血系/火系/固定/对战
- 「只数」填 N = 加 N 条独立条目（蛊虫不堆叠）
- 可设三项属性默认值、培养上限、_Skill/_Preference 目标值
- 可选「写入全部状态」/「写入全部技能库」
- **图标自动推断**：名字含「冰」→ bing，含「毒」→ du，等等

### 4.3.5 删除蛊虫

左侧多选后点「－ 删除选中」。

## 4.8 黑名单（工具栏两个）

### 4.8.1 功法黑名单

**用途**：把已知会让游戏卡死的功法先记下来避开。

**列入后**：
- 添加功法候选里**不显示**
- 不会被加给任何角色
- 已学列表悬停标「★ 在黑名单」

**管理**：
- 「＋ 从功法库添加…」：分类树 + 搜索 + 多选/全选
- 「－ 删除选中」
- 「清空全部」
- 逐条写**备注**
- 「⚠ 清除已学…」：把角色身上已学的黑名单功法删掉（可选范围）

### 4.8.2 道具黑名单

**用途**：主要是黑名单功法的**同名秘籍**。

**列入后**：
- 新增道具/一键添加全部/商店添加卖品候选里**不显示**
- 不会被加进包裹

**管理**：
- 「＋ 从道具库添加…」
- 「↧ 从功法黑名单导入同名秘籍」：一键导入

# 第五篇 · 存档结构原理（技术深入篇）

> 这一篇给**技术用户、想二次开发的人**看。普通用户可跳过。

## 5.1 es3 是什么？

**es3** = Unity **EasySave3** 的文本序列化格式。

**不是 JSON**，虽然看起来像。关键区别：
- 段名、字段名都用双引号
- 数值直接写数字（不像 JSON 需要严格转义）
- 可以内联（第一件物品的头在段头行）
- 结尾用 `,` 分隔

**示例**（ItemHad 段）：
```
		"ItemHad" : {"铜钱":{
				"_DressType" : 1,
				"_Count" : 998720404,
				"_Name" : "铜钱",
				"_LockHp" : 0,
				"_GetTimeNew" : 10101121200.116
			},"2纯铜矿":{
				"_DressType" : 1,
				"_Count" : 9999,
				"_Name" : "2纯铜矿",
				"_LockHp" : 0,
				"_GetTimeNew" : 0
			}
		},
```

**结构要点**：
- 段头：`"ItemHad" : {`
- 第一件物品头**内联**在段头行：`{"铜钱":{`
- 物品之间：`},"2纯铜矿":{`（前一件闭合 + 逗号 + 下一件头）
- 最后一件：`}` + 段尾 `},`
- 缩进：段头 2 个制表符、字段 4 个、物品闭合 3 个

## 5.2 关键设计原则：只重建 ItemHad 段

**为什么不全文件解析？**

1. es3 不是标准 JSON，通用解析成本高、易错。
2. 其它段落（装备/武功/地图等）不需要改，全解析等于白白承担风险。

**本工具的做法**：
```
lines = text.splitlines(keepends=True)          # 按行切分
start_idx = find_itemhad_line(lines)            # 找到 ItemHad 段头
items, indent, close_idx = parse_itemhad(lines, start_idx)   # 解析
# ... 用户在 GUI 上改 items ...
block = build_itemhad_lines(items, indent)      # 按原缩进重建
new_text = "".join(lines[:start_idx]) + block + "".join(lines[close_idx+1:])
```

**结果**：其它段落**逐字节保留**（包括空行、换行风格、缩进）。

## 5.3 兼容性踩坑（勿回归）

以下是**历史踩过的坑**，改动代码时务必注意：

### 坑 1：CRLF / LF 都要支持

存档通常是 `\r\n`。用 `$` 结尾的正则匹配行尾时，必须对 `ln.rstrip("\r\n")` 后的字符串匹配。

**错误写法**：`re.match(r'^\s*\}$', ln)`（CRLF 下 `\n` 前的 `\r` 会阻碍匹配）
**正确写法**：`re.match(r'^\s*\}$', ln.rstrip("\r\n"))`

### 坑 2：段头 `{` 的归属

`find_itemhad_line` 的正则 `"ItemHad"\s*:\s*\{` 会把 `{` 一起吞进匹配。所以**首件物品名**应从段头后的**剩余部分**匹配 `"([^"{}]+)":\{`，不要再补前导 `\{`。

### 坑 3：勿误中 ItemHadTemp

定位时用完整键名 `"ItemHad"`（带引号），可避免命中 `"ItemHadTemp"` 等前缀相似的段。

### 坑 4：BOM 兼容

UTF-8 BOM 要**剥离后处理**，写回时**原样补回**。

### 坑 5：`_DressType` / `_LockHp` / `_GetTimeNew` 保留原值

**历史教训**：曾把 `_LockHp` 硬编码为 0，导致参考存档往返不一致（该档有 7 处 `_LockHp=100`）。必须保留原值，新增道具才用默认值（1/0/0）。

## 5.4 结构索引与性能优化

### 5.4.1 结构索引

**问题**：大文件（8.6MB）每次扫描结构符（`{ } [ ] ,`）都要几百毫秒。

**方案**：一次扫描建索引，之后在索引上线性扫描。

```python
def _struct_index(text):
    # 1. 用 str.find 跳过字符串
    # 2. 用 str.join 拼出 clean（字符串区挖成等长空格）
    # 3. 一次正则找全部结构符
    # 4. 建同型括号配对表
    return poss, chars, pairs
```

**关键优化**：
- **配对表 `pairs`**：建索引时用栈一次算出每个括号的配对位置。`_matching_end` 变成 O(1) 查表（200ms → 0.3ms）。
- **同文本缓存**：`_SCAN_CACHE` 只缓存最近一份文本，同 str 对象命中 0 成本。

### 5.4.2 局部配平

**问题**：某些操作只需在一个小容器内配平，但用整档索引会因索引失效而冷建（1.3s）。

**方案**：`_local_span_end` 逐字符配平（字符串整体跳过），适合小段。

### 5.4.3 fast 定位

**问题**：`_ActiveMap` 这类字段全档只出现一次，但 `_locate_container` 要逐层扫大容器（1.7s）。

**方案**：`_unique_field_open` 用 `str.find` + 检查唯一性 + 局部配平（毫秒级）。

### 5.4.4 索引打补丁

**问题**：每次改动后 `self._text` 变成新对象，索引缓存失效。

**方案**：`_apply_subs` 重建文本时，如果原文本是缓存索引所属，**按位移打补丁**：
- 段外结构位置整体平移 delta
- 段内替换文本重扫结构字符
- 重建配对表

**失败时**：只清缓存，下次冷建，不影响正确性。

### 5.4.5 异步预热

**问题**：改动后下一次操作会在主线程冷建索引（1.3s 卡顿）。

**方案**：`_mark_dirty` 里调 `_preheat_index_async(self._text)`，后台线程把新文本的索引建好。

## 5.5 多线程与 UI 响应性约定

> 这是 v2.14.5 固化的**强制约定**，任何改动必须遵守。

### 三条硬规矩

1. **纯计算 / 文件 IO 一律后台**：走 `_run_bg(work, msg)`。worker 里**绝不碰 Qt 控件**。
2. **Qt 控件只能在主线程建**：长构建要**分块 + `_pump()`** + 重入守卫。
3. **批量列表/表格操作必须批量化**：
   - 候选列表「全选」用 `_select_enabled_items`（区间 + `QItemSelection` 一次性提交）
   - 批量建项用 `addItems` 而不是循环 `addItem`
   - 表格加行用 `_append_rows_local` 而不是整表重建

### 实测基准（8.6MB 真实档）

| 操作 | 耗时 |
|------|------|
| 打开端到端 | 7.3s（主线程 ~3.3s，有进度） |
| `char_model` | 2.9s（后台） |
| 地图刷新 | 0.02s |
| 单字段写回 | ~0.2s |

### 已知硬成本

- 单次 `_apply_subs` ≥0.2s（Python 字符串拼接硬成本）
- 道具表重建 ~1s（Qt 主线程限制）
- 角色页构建 ~1.8s（Qt 主线程限制）

## 8.2 关键设计约定（勿破坏）

### 8.2.1 纯函数与 GUI 分离

**原则**：所有解析、生成、定位、改写的逻辑都是**模块级纯函数**，不依赖 GUI。

**好处**：
- 可以单独测试
- 可以在脚本里复用
- 方便后台线程调用

**新增功能时**：先写纯函数，再写 GUI 调用。

### 8.2.2 只重建必要的段

**原则**：改哪段就只重建哪段，其它段落**逐字节保留**。

**实现**：所有段的重建都走 `_apply_subs(text, [(s, e, v)])`，它只替换指定区间。

### 8.2.3 用 `_apply_subs` 而非手动拼接

**错误写法**：
```python
text = text[:s] + v + text[e:]
```

**正确写法**：
```python
text = _apply_subs(text, [(s, e, v)])
```

**原因**：`_apply_subs` 会顺带维护结构索引缓存，避免下次操作冷建。

### 8.2.4 写路径统一走 `_mark_dirty`

**原则**：任何修改 `self._text` 的地方都要调 `_mark_dirty()`。

**作用**：
- 标记未保存
- 触发索引异步预热
- 刷新状态灯

### 8.2.5 最小跨度改写

**原则**：替换文本越短，`_apply_subs` 越快。

**反例**（`friends_move` 早期写法）：
```python
# 重建整个容器体（2.4MB）→ 1.6s
new_body = ",".join(entries)
text = _apply_subs(text, [(container_open, container_close, new_body)])
```

**正例**：
```python
# 只改差异区（尾区 + 被删段）→ 0.6s
subs.append((tail_start, close, new_tail))
subs.append((ents[i][1], end, ""))
text = _apply_subs(text, subs)
```

### 8.2.6 按身份重定位而非复用偏移

**原则**：文本改动后，缓存里的绝对偏移会失效。**按名字/序号重新定位**，不要用「按 delta 平移」。

**原因**：多次改动会累积误差，导致读到错的字段。

**例子**：
- 蛊虫：`chong_entry_open(text, idx)`
- 装备：`equip_instance_open(text, name, idx)`
- 功法：`kangfu_add` 内部自行重定位

## 8.3 如何新增一个功能

**以「新增一个页签」为例**：

1. **设计纯函数**：解析、读取、改写都写成模块级纯函数。
2. **写测试**：先写 `smoke_test.py` 的用例，确保纯函数正确。
3. **写 GUI**：在 `MainWindow` 里加构建方法、事件处理。
4. **写 GUI 测试**：在 `smoke_gui_test.py` 加用例。
5. **更新帮助文本**：`_HELP_TEXT` 加说明。
6. **更新文档**：本手册 + 软件升级迭代记录。
7. **更新版本号**：`__version__` 改为新版本。
8. **备份版本**：把主程序复制到 `version/` 目录。

## 8.4 如何扩展纯函数库

**示例：写一个「批量改装备等级」的纯函数**：

```python
def set_all_equip_lv(text, lv):
    """把所有装备实例的 _Lv 改成 lv。
    
    返回 (新文本, 改了件数)。
    """
    model = equip_skill_model(text)
    count = 0
    for name, spans in model:
        for inst_open, _inst_close in spans:
            nt, changed = equip_set_scalar(text, inst_open, "_Lv", lv)
            if changed:
                text = nt
                count += 1
    return text, count
```

**注意**：
- 遍历时**从后往前**（避免偏移失效）
- 每次改动都走 `equip_set_scalar`（内部走 `_apply_subs`）
- 返回新文本和统计

# 第九篇 · 常见问题（FAQ）

## 9.1 基础问题

**Q：这是什么？安全吗？**

A：这是一个存档修改器，只修改游戏的 `.es3` 存档文件，不改游戏程序。安全的前提是**先备份**。

**Q：支持哪个版本的游戏？**

A：面向《灵兽江湖》的 es3 文本存档。只要存档是 es3 格式，就支持。

**Q：需要联网吗？**

A：不需要。完全本地运行。

**Q：会不会被封号？**

A：这是**单机游戏**，不存在封号。但改太夸张可能导致游戏出问题，先备份。

## 9.2 打开/保存

**Q：提示「未找到 ItemHad 段」怎么办？**

A：可能原因：
- 文件不是 es3 文本（可能是二进制）
- 存档损坏
- 该存档确实没有 ItemHad 段（如纯自定义存档）

**Q：大文件打开很慢？**

A：正常。8.6MB 存档打开约 7 秒，期间窗口不卡（有进度）。这是 Qt 主线程构建 UI 的硬成本。

**Q：保存后游戏读不出来？**

A：可能改坏了。用备份恢复。**第一次改务必先另存为测试**。

**Q：状态灯红了，关了程序会怎样？**

A：修改会丢失。**红的时候务必先保存**。

## 9.3 道具相关

**Q：为什么「一键添加全部道具」只加了部分？**

A：会剔除：
- 已有道具
- 装备类（equip）—— 用「＋添加装备」加
- 技能合成类（skillcom）—— 不显示
- 道具黑名单

**Q：道具名带引号（如 `碎“肉”`）能加吗？**

A：能。程序自动转义成游戏格式。

**Q：数量上限是多少？**

A：2,100,000,000（21 亿）。

## 9.4 角色/功法

**Q：改等级后游戏里显示不对？**

A：有些显示是游戏实时算的，存档里改的是基础值。可能需要进游戏触发一次刷新。

**Q：添加功法提示「该角色缺对应段」？**

A：该队友没有那一段（如没有轻功段）。这是存档本身的限制，无法添加。

**Q：为什么已装备的功法加不进去？**

A：这是**故意**的。已装备的功法存在独立对象里，往段里再添一份会变成同名两份，游戏里卸不下来。工具会跳过并提示。

**Q：功法黑名单加了但还能加？**

A：检查：
- 黑名单文件是否写盘成功
- 是否重启了程序（黑名单与存档无关，但改完要重载）
- 名字是否带零宽字符

## 9.5 队伍

**Q：加入队伍后游戏里没显示？**

A：加入队伍只改归属，**出战 3 人要在游戏里点选**。

**Q：改为离队后出战名单还在？**

A：工具会自动把该队友从 `BattleFriend` 摘掉。若游戏里仍显示，重新载入存档。

**Q：搬移后队友属性变了？**

A：不会。整条搬移，逐字节不动。若有异常，检查是否同名队友。

## 9.6 性能

**Q：改一个值卡一下？**

A：单次写回 ≥0.2s，是 Python 字符串拼接的硬成本。已优化到最小。

**Q：全选 4000 个道具很慢？**

A：v2.14.4 起已优化到 50ms。若你的版本慢，升级。

**Q：大档角色页切页卡？**

A：首次构建角色页约 1.8s，之后切页不卡。

## 9.7 数据/文件

**Q：`设置.json` 存了什么？**

A：批量目标值、商店目标值、折扣、刷新日、保存后关闭、自动刷新、蛊虫默认值、功法等级。

**Q：`历史记录.json` 在哪？**

A：程序目录。可以在「最近 ▾」菜单里清空。

**Q：黑名单文件能不能手动编辑？**

A：可以。格式兼容 `["名1","名2"]` 和 `{"items":[{"name":"名","note":"备注"}]}`。

**Q：`道具名.json` 越来越大怎么办？**

A：不会。读档自动去重，稳定在 4000+ 个。

## 9.8 错误/异常

**Q：提示「程序正忙」？**

A：有后台任务在跑。等几秒重试。

**Q：提示「未找到 xxx 段」？**

A：该存档没有这个段（如没蛊虫、没商店）。属正常。

**Q：批量改折扣后存档坏了？**

A：v2.8.4 起有防御：结果异常会拒绝采纳。若仍出问题，反馈 GitHub Issues。

## 9.9 开发相关

**Q：能写脚本调用吗？**

A：能。所有纯函数都是模块级的，见第六篇案例七。

**Q：能加新功能吗？**

A：能。这是 MIT 协议。见第八篇。

**Q：怎么提交 bug？**

A：通过 GitHub Issues。
